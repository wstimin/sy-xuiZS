# 商业版生产验收清单

本文用于在测试 VPS 上验证 `sy-xuiZS` 商业版。测试机不得承载正式用户或正式节点。

## 1. 发布与安装

1. 确认 GitHub Release 包含 `xui-zhushou-linux.tar.gz`、带版本号的压缩包和 `SHA256SUMS`。
2. 在一台全新 VPS 上运行 README 中的一键安装命令。
3. 确认 `/opt/3xui-deploy-assistant/VERSION` 和 `/api/health` 均返回 `3.0.0`。
4. 确认数据库位于 `/var/lib/xui-assistant/app.db`，权限不允许普通用户读取。
5. 重启服务器，确认 PM2 自动恢复服务，用户数据仍然存在。

## 2. 账户与权限

1. 首次访问只能创建一个管理员账号。
2. 创建管理员后，首次初始化接口必须拒绝再次创建管理员。
3. 开启注册后创建普通用户，关闭注册后确认新用户无法注册。
4. 普通用户访问管理接口必须返回无权限。
5. 禁用普通用户后，确认其无法继续执行搭建。

## 3. 套餐与订单

1. 创建测试套餐：有效期 1 天，面板 1 次，节点 2 次，每日限制分别为 1 和 2，并发限制 1。
2. 普通用户创建订单，确认订单状态为待支付且尚未获得权益。
3. 管理员确认收款，确认订单只会成功处理一次。
4. 修改套餐后，确认已支付订单仍按下单时的套餐快照发放。
5. 到期后确认用户不能再预占搭建次数。

## 4. 真实面板搭建

1. 准备一台兼容的空白 Linux VPS 和独立测试域名。
2. 使用普通用户执行一次面板搭建，确认原有 SSH 检查和安装步骤正常。
3. 验证安装成功后面板次数从 1 变为 0。
4. 再次执行时应在连接 VPS 之前被系统拒绝。
5. 使用错误 SSH 凭据执行失败任务，确认次数自动退还。
6. 在安装过程中主动断开浏览器，确认任务进入“不确定”状态，不自动退款。
7. 管理员核实目标 VPS 后，将不确定任务处理为成功或失败，并确认次数对应结算。

## 5. 真实节点搭建

1. 使用刚安装的测试面板创建第一个节点，确认节点次数减少 1。
2. 创建第二个节点，确认节点次数归零。
3. 第三次请求应在调用 3x-ui API 前被拒绝。
4. 使用错误 Token 触发明确失败，确认节点次数退还。
5. 测试一次带 SOCKS 路由的节点创建，并确认失败回滚后 Xray 模板和入站状态正确。

## 6. 升级与回滚

1. 记录当前用户、订单、权益和任务数量。
2. 再次执行安装命令进行同版本更新，确认数据库备份出现在 `/var/backups/xui-assistant`。
3. 更新后核对所有记录数量和剩余次数不变。
4. 使用无效测试构建包验证健康检查失败时应用目录能够回滚。
5. 回滚后再次核对数据库内容和 PM2 服务状态。

## 7. 上线门槛

- 全新安装、重启、更新和回滚均通过。
- 面板与节点各至少完成一次真实搭建。
- 成功扣次、明确失败退款、不确定任务冻结均符合预期。
- HTTPS 已启用，`.env` 中设置 `SESSION_COOKIE_SECURE=true`。
- 数据库和备份目录权限已检查。
- 云安全组只开放实际需要的端口。
- 已准备用户协议、退款规则、禁止用途说明和支持联系方式。
